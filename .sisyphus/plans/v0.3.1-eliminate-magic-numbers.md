# KID-WATCH v0.3.1 — Eliminate Magic Numbers

## TL;DR

> **Quick Summary**: Extract ~140 hardcoded magic numbers across the KID-WATCH codebase to named constants. Pure refactoring — zero behavior changes. Every test that passed before must pass after.
>
> **Deliverables**:
> - Named constants for all detection thresholds, timing values, and UI dimensions
> - Constants organized at file/class level (no new files created)
> - Shared constants in `config.py`
> - File-specific constants as class or module constants
> - Dashboard constants stay in `dashboard.py` (UI-specific)
>
> **Estimated Effort**: Small (30-45 minutes)
> **Parallel Execution**: YES — 11 tasks can run in 3 parallel waves
> **Critical Path**: Phase 1 (detection logic) → Phase 2 (legacy detectors) → Phase 3 (dashboard)

## Context

### Original Request
Eliminate magic numbers across the codebase to improve maintainability and readability. All values must stay EXACTLY the same — this is pure refactoring with zero behavior changes.

### Scope
- **Detection logic files**: calibration.py, posture_detector_yolo.py, movinet_detector.py, gaze_detector.py, phone_detector.py, engagement.py, state_machine.py
- **Legacy detector files**: study_detector.py, posture_detector.py
- **Dashboard files**: dashboard.py, utils.py
- **Total magic numbers**: ~140 across all files

### Strategy
- Create constants at the TOP of each file as class-level or module-level constants
- Do NOT create new files (no `ui_constants.py`, no `detector_constants.py`)
- For values shared across files, put them in `config.py`
- For file-specific values, put them as class constants or module constants in that file
- Dashboard UI constants stay in `dashboard.py` (they're UI-specific, not shared)
- Run syntax check after EVERY file change
- Verify behavior hasn't changed by running the app

## Key Decisions

1. **No new files**: Keep constants in the files that use them. This avoids circular imports and keeps related code together.
2. **Class-level constants**: For detector classes, use class constants (e.g., `CalibrationEngine.NEUTRAL_SETTLE_SECONDS`).
3. **Module-level constants**: For standalone functions or utilities, use module constants.
4. **Shared constants in config.py**: Only if a constant is used in 2+ files. Otherwise, keep it local.
5. **Dashboard constants stay in dashboard.py**: UI-specific constants are not shared across the codebase.
6. **Exact value preservation**: Every constant value must be EXACTLY the same as the original hardcoded value. No rounding, no approximation.
